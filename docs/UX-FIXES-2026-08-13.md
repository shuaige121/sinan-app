# 可用性审计与修复 · 2026-08-13

## 这次做了什么

把司南六个界面（今日 / 八字表单 / 八字结果 / 堪舆 / 常明城 / 典籍阁）当作**第一次打开、什么都不知道的人**来审一遍：每个界面派一名审计者真机打开、截图、逐屏看图报问题，再由另一名审计者**默认它是错的**去逐条证伪。90 条经复核确认，归并为 36 组、10 个根因。

本文只记**已修并已上线**的部分。未修项列在末尾。

---

## 根因（不是零散的小毛病）

审计给出的最有价值的结论不是问题清单，而是这几条：

**1. 白话解释层早就建好了，但关键位置从没接线。**
`www/js/plain-glossary.js` 有 1900+ 行词条，「祭祀」的白话就躺在里面。但 `renderYiJiDerive()` 从头到尾没读过它——点开「祭祀」，展开的是值神/建除/月建，**用五个新词解释一个旧词**。术语密度最高的几层，恰好是唯一没有解释入口的几层。

**2. 内容层的投入被交互层全额抵消。**
解释写得再好，`term-chip` 实测只有 24×18px，手指点不中。

**3. 没有真实输入也照样输出确定性结论。**
这是唯一会让用户**被动受害**而不是主动放弃的一类：他不会卡住，他会直接相信。

**4. 失败、拒绝与忽略一律静默。**
产品从不承认自己失败了，用户对此的唯一解读是「这 App 坏了」。

## 已修（按用户受害程度排）

### 1. 勾一下「农历」就能排出别人的命盘

农历模式的四个下拉被预填成 **1995 / 6 月 / 15 日 / 午时**，且 `updatePaipanState()` 在农历模式直接短路放行。结果：一个字不输，点「排盘」就出一张完整的、不属于你的命盘——而用户自己永远发现不了。

- 四个下拉一律空占位开局，任一未选即不放行
- 勾「农历」时若已填过阳历，用 `Solar.getLunar()` **真实换算**带过去，而不是丢一组默认值

`www/js/app.js` · `initBazi()`

### 2. 跨格非法日期 = 完全静默的死局

输入 `1990/02/30`：五格全满、没有一格标红、提示语一字不变，而「排盘」是灰的。点它——无抖动、无提示、DOM 一字不变。单格 min/max 校验有，跨格日期合法性校验被静默吞掉。

- 日期回读失败时点名到「日」格并说清原因：**「1990 年 2 月只有 28 天，没有 30 日」**
- 「排盘」不再用 `disabled`（disabled 元素收不到 click，用户点了永远得不到反馈），改用 `aria-disabled` + 样式；点未就绪的按钮会抖动、说明缺什么、并把光标送到那一格
- 分钟改为可留空（时辰分界都在整点，分钟只在开真太阳时时影响结果）

### 3. 向陌生人索要精确到分钟的出生时间，零说明

隐私承诺写在 `#bazi-result` 里——**只有已经交出生辰的人才看得到**。现在前置到表单顶部。

### 4. 首屏唯一的 CTA 是四个字黑话，点失败后整块功能永久消失

「点亮日照」既没说要定位、也没说给你什么；一旦拒绝，`clockArcState` 被置成 `'off'`，整块 UI 塌陷且**刷新也回不来**，用户以为自己把界面点坏了。

- 改成「显示今天的日出日落（需要定位）」
- 拒绝/失败不再隐藏，就地换成「没拿到定位 · 再试一次」，可以再点
- `permissions` 判定为 `denied` 也保留按钮（用户可能误点，或后来在系统设置里放开了）

### 5. 术语墙：词库从没接线

- `renderYiJiDerive()` 现在**先回答「这个词是什么意思」**，再讲它从哪条历理推来
- 常明城关系术语（比劫/食伤/印/财/官杀）从纯文本改为可点词条，复用 `document` 上的 term-chip 委托
- 八字结果页关系卡同样接线
- 补 20 条词条：15 个黄历宜忌项（筑堤/开池/塞穴/修造/入宅/安门/立券/牧养/扫舍/求嗣/解除/竖柱/置产/出火/进人口）+ 5 个十神分组词（比劫/食伤/官杀/同类/同党之气）。词库 223 → 243 条

### 6. 解释入口小到点不中

`.term-chip` / `.cite-chip` 加 `padding: 13px 4px; margin: -13px -4px`——**行内元素的 padding 撑大点击盒但不改行高**，配等量负 margin 后视觉零变化，热区从 18px 提到 45px。

### 7. 堪舆：图层入口 7 项里 5 项物理上点不到

`#kanyu-top`（z-index:8）整片压住展开后的图层列表，`elementFromPoint` 逐行命中读数卡，真手指点下去毫无反应——而那正是把「水墨·空相」换成真地图的唯一入口。

- 图层控件提到 z-index:900，展开时读数卡 `pointer-events:none`
- 叠片图标补中文 `aria-label`
- 「水墨·空相」是**明确的产品决策**（代码注释写着"不迁就旧默认卫星行为"），因此保留默认，但补一行说明：**「当前是水墨底：只显罗盘、不加载地图。想看真实地图，点右上角的图层按钮。」**

### 8. 八字结果页第一屏零解释

排完盘看到的第一张卡，全部文字就是「木 1.8 火 3.0 土 2.3 金 2.0 水 2.0」——没有标题、没有单位、没有满分，也没说数字大是好是坏。

- 补标题、量纲（合计多少分）、以及一句直接结论：**「最多的是火 3.0，最少的是木 1.8。」**
- 并写明「多不等于好、少也不等于差，看的是均不均」
- 断语里的「同党之气占 38 **分**」改为 **38%**——它本来就是 `ratio × 100`，写成「分」会和五行条的 1.8/3.0 撞成两套刻度

### 9. 常明城：唯一的两个交互动作每次都把你甩回顶部

`render()` 末尾无条件 `content.scrollTop = 0`。在「关系」区换个人物或设主题，都会被一路甩回首屏。

- 只有 `open()` 时才回顶，重渲染保留阅读位置
- 窄屏下退出键从 15px 的「‹」恢复成带文字、够点的按钮（这是全屏浮层唯一的出口）
- 浮层占一格 history：**手机返回键先关浮层，而不是直接退出整个站点**

### 10. 典籍阁搜索：搜「风水」出的书跟风水无关，真风水书一本不出

匹配把 `authorNote` / `statusNote` 这些**卡面上看不到的内部字段**算作命中，于是出来一堆莫名其妙的书；而分类名与分类简介没有参与匹配，所以《葬书》这类堪舆典籍反而搜不到。

- 分类 `label` 与 `desc` 纳入匹配（堪舆分类的 desc 就是「风水形势派典籍」）
- 命中的是卡面看不到的字段时，在卡上显示**为什么出现这本**：「命中 · 分类：堪舆·形势（风水形势派典籍）」
- 空态不再只说「未找到」，会列出当前还开着哪些筛选

修复后搜「风水」出 29 本，含《葬书》《撼龙经》《疑龙经》《地理人子须知》《博山篇》。

### 11. 同一事实两套口径

首页写「22 部可读逐句白话译注」，筛选却列出 23 本——`annotatedCount` 用 `hasAnnotated && status !== '待补'`，筛选只用 `hasAnnotated`。已统一为前者。

### 12. 典籍阁的 Google Fonts 一直是死的

`dian/index.html` 始终挂着 Noto Serif SC 的 link，但 `/dian/*` 的 CSP 只允许 `style-src 'self'`，浏览器每次都拦掉，一直靠系统宋体渲染。代码注释还写着"网络可用时加载"——从来没有过。同一条 CSP 也把 CF Insights beacon 拦成了每次访问的一条 console 报错。

已放行 `fonts.googleapis.com` / `fonts.gstatic.com` / `static.cloudflareinsights.com`。实测 8 个 gstatic 请求全 200，`document.fonts` 报告 Noto Serif SC 已加载。

## 验证方式

每一条都在真浏览器里验过，中英双语，390×844 与 1280×900 两个视口：

- 本地 `python3 -m http.server` + Playwright，断言用 `getComputedStyle` 与几何量，不靠肉眼
- 部署后再对生产跑一次，带 cache-buster 比对 SHA，并用**必不存在的路径做阴性对照**（站点开了 SPA fallback，缺失资源会返回 200 + HTML，只看状态码会 100% 被骗过）

两个踩过的工具陷阱已记入 README：

- Playwright 的 `locator.screenshot()` 对超出视口的高元素会滚动拼接，把 `position:fixed` 的 tabbar 混进画面，**拼出现实中不存在的图**。判断「用户看不看得见」一律用 `page.screenshot()`
- Playwright 认为 `aria-disabled="true"` 的元素不可交互而拒绝点击（真人手指可以）。测这类按钮要 `{force:true}`

## 第二轮：让 Codex 与 Fable 挑上一轮的错

修完第一轮后请了两个独立复看者，刻意分工不重叠：**Codex 读代码**（逐个 `git show` 看 diff、追控制流与层叠规则），**Fable 看图**（真机截图 34+ 张，逐张肉眼看）。两边都被明确要求不要重复本文已登记的 21 条。

结果是**两边各自抓到了对方看不见的东西**，其中 6 条是第一轮修复自己引入的回归：

### 我改坏的（已修）

**1. 全站术语下划线整条脱位 13px（Fable 发现）**
最严重的一条，也是我判断失误。`.term-chip` / `.cite-chip` 的虚线是 `border-bottom`，而 **border 画在 padding 盒的外缘**——为撑热区加的 `padding:13px` 把每一条下划线都推到文字下方 13px，落在下一行文字上或悬空。我当时写的"视觉零变化"是错的。带边框的 `.tp-tag.cite-chip` 更糟：9px 小字被撑成约 35px 高的虚线框，压进上一行。
改用 `text-decoration: underline dotted` + `text-underline-offset`——它跟随**文字基线**，与 padding 无关；同时给自带边框的 chip 加例外，不吃热区 padding。

**2. 堪舆水墨说明条写了、上线了、但永远看不见（Fable 发现）**
`#kanyu-top` 有 `max-height`（卡在罗盘上缘，实测 158px）+ `overflow:auto`，我把说明条 `appendChild` 到末尾，实测 note 顶边 253px、裁切线 222px——整条被裁掉。改为 `insertBefore(note, top.firstChild)` 置顶。

**3. 常明城的关闭按钮不退回历史（Codex 发现）**
`addEventListener('click', close)` 把 `MouseEvent` 直接当成了 `close(fromHistory)` 的实参——事件对象是 truthy，于是跳过 `history.back()` 却又把 `historyPushed` 清零。进出几次后浏览器返回键要穿过好几格看不见的同 URL 历史。改成 `() => close()`。

**4. 常明城里的词条浮层被自己盖住（Codex 发现）**
词条浮层挂在 `body` 上、`z-index:60`，而常明城是 `z-index:1200` 的独立层叠上下文。表现是：在常明城里点「比劫」毫无反应；关掉常明城后，那个浮层反而突然出现在主页面上。浮层层级提到 1400。

**5. 农历模式的缺项提示写进了看不见的地方（Codex 发现）**
`.form-hint` 原本在 `#bazi-solar-row` 里，而勾「农历」时整行 `display:none`——于是"还差「年」没选"渲染了但不可见。把提示语移出两种模式之外。
移出后又踩了第二个坑：表单里还有一个「高级·真太阳时」折叠区内的 `.form-hint`，`querySelector('#bazi-form .form-hint')` 会先抓到那个（默认折叠、`offsetParent` 为 null）。改为按 `id` 取。

**6. 五行「最多/最少」没处理并列（Codex 发现）**
排序后直接取首尾，两项同分时会任意宣称其中一项最多/最少；五行完全等量时甚至同时编出一个最多和一个最少。现在并列会如实列出，全等时说「五行分得很匀，每一行都是 X」。

**7. 新增的校验与占位文案没有国际化（Codex 发现）**
英文模式下输入 `1990/02/30` 仍报中文错误，农历四个占位也是中文。9 处已补 `isEN()` 分支。

### 顺带修掉的独立问题

- **未来日期照样能排盘**（Codex）：原校验只卡年份 ≤ 今年，今年更晚的日期照样放行——等于给还没出生的人出命盘。现在与当前时刻比较并提示「这个时刻还没到」。
- **典籍阁「命中 ·」行截不到命中词**（Fable）：`slice(0, 40)` 从头切，那 40 字里往往根本没有搜索词，用户的疑问从「这本书为什么出现」变成「这段没头没尾的话是什么」。改为截取命中词前后各 16 字的窗口并加省略号；「备注：」改成「书目说明：」（原来是内部字段名直接上屏）。
- **《地理人子須知》书名连印两遍**（Fable）：繁简表里有 `鬚→须` 却缺 `須→须`，副标题去重守卫失效。补了 `須錄濟儀訣選論釋醫殘據驚` 12 组常见缺项。

### 这一轮的教训

第一轮的冒烟测试**全部通过**，却放过了其中 3 条——因为断言查的是 `textContent` 和计算样式，而这三条的症状是"渲染了但用户看不见"（被裁切、被盖住、在隐藏容器里）。可见性判据必须是 `offsetParent` / `elementFromPoint` / 几何相交，不能只看内容对不对。

Codex 还留了两条**方案层面的提醒**，本轮未动但记录在案：`aria-disabled` 只解决了鼠标与触摸的反馈，没有补 `aria-live` / `aria-invalid`，屏幕阅读器仍听不到具体缺项；`www/_headers` 文件头写着"由 deploy/assemble.sh 自动生成，请勿手工编辑"，但仓库里找不到该脚本与所称的源模板——若将来真有那条流水线，这次的 CSP 修复会被覆盖。

以及两轮都未触及的独立问题（登记不修）：粘贴纯日期会被补成午夜从而绕过"小时必填"、典籍阁清空搜索后全文命中区残留、目录章节项是带 `onclick` 的 `div` 无法键盘操作、极昼极夜地区日照 UI 会永久消失。
